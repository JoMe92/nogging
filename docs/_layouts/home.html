Why Nogging?

  • Agents overwrite each other

    ProblemSeveral agents on one repository overwrite each other and the plan.

    SolutionOne Git worktree and one claimed Bead per agent.

  • Agents rewrite the spec

    ProblemAn agent “fixes” the specification to match its code.

    SolutionOnly a planning session writes openspec/; execution roles are fenced out (boundaries).

  • Runs die, state is lost

    ProblemA run dies and the state is lost.

    SolutionClaims, notes and worktree records persist, with documented recovery.

  • “Done” is only a claim

    Problem“Done” is a claim, not a record.

    SolutionEvery closed Bead carries a commit and an evidence note that sync mirrors into OpenSpec.

  • More than one agent CLI

    ProblemYou use more than one agent CLI.

    SolutionThe same loop for Claude Code, Codex and Pi, with Antigravity (experimental).

How it works

One plan, one task per agent, and evidence that flows back.

Safety

Nogging installs repository instructions and Git hooks, and can launch coding agents with filesystem, network and shell access. Read the security model before you enable full access or background services, and start with restricted authority.
