# Product-name research, round 2 — 2026-09-10

Status: **technical shortlist; direct trademark clearance pending**

This round follows the Product Owner's rejection of DeliveryLoom and the
collision review that rejected CodeAgentOS. It deliberately avoids `SpecForge`,
`Agent OS`, `Code Agent`, and close variants. The target remains a short English
name for the future of AI-agent software development.

## Checks

On 2026-09-10 each shortlisted lowercase identity was checked against Verisign
`.com` RDAP, Google Registry `.dev` RDAP, npm, PyPI, GitHub exact repository
names, GitHub accounts, and quoted exact-name web searches. Each returned no
exact record. Indexed exact-name searches scoped to the USPTO search domain
also returned no result.

This is a point-in-time technical screen, not a reservation or legal opinion.
Before claiming a name, the owner must perform direct exact and similar-mark
searches in [USPTO Trademark Search](https://tmsearch.uspto.gov/),
[EUIPO eSearch](https://euipo.europa.eu/eSearch/), and the
[WIPO Global Brand Database](https://branddb.wipo.int/), then repeat the live
domain and account checks.

## Ten new proposals

| Rank | Name | Why it fits | Trade-off |
| ---: | --- | --- | --- |
| 1 | **DevSynth AI** | AI agents synthesize plans, tasks and code into working software. Short, technical and easy to say. | “Synth” may initially suggest synthetic data or audio. |
| 2 | **BuildWeave AI** | Multiple agent, planning and evidence threads are woven into one delivery flow. | Slightly metaphorical; needs the one-line product explanation. |
| 3 | **DevFabric AI** | Presents the product as connective infrastructure for AI-driven development. | “Fabric” is common in infrastructure naming and needs similar-mark review. |
| 4 | **BuildNexus AI** | A central coordination point for agents that plan, build and verify software. | “Nexus” is widely used as a component in other technology names. |
| 5 | **BuildSynth AI** | Emphasizes agents converting intent into verified builds and releases. | Can sound focused on compilation rather than the full lifecycle. |
| 6 | **DevWeave AI** | Memorable description of joining specifications, agents, tasks and Git evidence. | Less immediately “platform-like” than DevFabric AI. |
| 7 | **BuildOrbit AI** | Agents and delivery tools operate around one controlled workflow. | “Orbit” communicates coordination but not software by itself. |
| 8 | **BuildFabric AI** | A technical fabric connecting agent workflows across software delivery. | Longer and more infrastructure-oriented. |
| 9 | **DevSwarm AI** | Clearly evokes multiple AI agents collaborating on development work. | “Swarm” can imply uncontrolled autonomy, conflicting with the safety model. |
| 10 | **BuildRelay AI** | Captures reliable hand-offs from intent to agents to verification. | Sounds like one pipeline stage unless positioned carefully. |

## Reserve candidate

**BuildSwarm AI** also passed the technical namespace screen, but ranks below
DevSwarm AI because it is less explicit about software development and carries
the same uncontrolled-swarm association.

## Recommendation

The strongest three for direct trademark review are:

1. **DevSynth AI** — strongest balance of brevity, future orientation and clear
   development context.
2. **BuildWeave AI** — best expression of the product's actual multi-system
   architecture.
3. **DevFabric AI** — strongest platform/infrastructure positioning.

No name, domain, account or package namespace has been claimed by this work.
