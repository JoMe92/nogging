# Product-name research — 2026-09-09

Status: **technical shortlist; trademark clearance pending**

## Product concept

The product is a local-first system for AI-assisted software delivery. It lets
teams turn approved intent into executable agent work and verifiable Git
evidence while preserving explicit human control over planning and acceptance.

The public name should therefore be:

- short, English and easy to pronounce and remember;
- recognizably connected to AI agents and software development;
- broad enough for the future of software delivery, not one current vendor;
- usable as a command, repository, package scope and web identity;
- distinctive enough to search without implying vendor affiliation.

## Method and limits

Exact lowercase names were checked on 2026-09-09 against:

- Verisign RDAP for `.com`;
- Google Registry RDAP for `.dev`;
- the npm and PyPI registry APIs;
- GitHub exact repository-name search and the GitHub user/account API;
- quoted general-web searches, including indexed USPTO and EUIPO pages.

`NO RECORD` below means only that the queried service returned no exact record
at that moment. It is not a reservation, a guarantee of registrar availability,
or legal clearance. Search-engine indexing is not a substitute for direct
searches in [USPTO Trademark Search](https://tmsearch.uspto.gov/),
[EUIPO eSearch](https://euipo.europa.eu/eSearch/), and the
[WIPO Global Brand Database](https://branddb.wipo.int/). Those direct searches,
similar-name review and intended-market legal judgment remain mandatory before
selection.

The registry queries used the exact lowercase candidate in these forms:
`/com/v1/domain/<name>.com`, `/rdap/domain/<name>.dev`,
`registry.npmjs.org/<name>`, `pypi.org/pypi/<name>/json`, GitHub
`<name> in:name` followed by exact-name filtering, and `users/<name>`. The
indexed mark screen used quoted exact names restricted separately to
`tmsearch.uspto.gov`, `euipo.europa.eu/eSearch`, and `branddb.wipo.int`; it
returned no indexed exact result for the twelve shortlisted spellings. Direct
database and similar-mark searches remain pending as stated above.

## Shortlist

Every candidate in this table returned `NO RECORD` for `.com`, `.dev`, npm,
PyPI, an exact GitHub repository name and an exact GitHub account during the
technical screen.

| Rank | Candidate | Meaning and positioning | Main trade-off |
| ---: | --- | --- | --- |
| 1 | **CodeAgentOS** | An operating layer for agents that build software. Immediately understandable and strongly future-facing. | “OS” creates an expectation of a broad platform rather than a small workflow tool. |
| 2 | **AgentCodeOS** | A software-delivery operating system centered on AI agents. Short and direct. | Slightly less natural English word order than CodeAgentOS. |
| 3 | **AgentBuildOS** | Agents coordinate the complete build/delivery process, not just code generation. | “Build” can be mistaken for compilation only. |
| 4 | **CodeAgentsOS** | Explicitly communicates multiple collaborating coding agents. | Plural form makes the command/package name a little heavier. |
| 5 | **DevAgentsOS** | Clearly targets developer agents and an extensible platform. | “Dev” is concise but less polished outside developer audiences. |
| 6 | **AgentCodeKit** | A practical toolkit for agent-driven software development. | “Kit” sounds smaller and less like a complete operating model. |
| 7 | **DevAgentKit** | Direct, descriptive and easy to understand for developers. | More generic and less defensible as a brand. |
| 8 | **FutureCodeOS** | Positions the product around the future operating model of software creation. | Does not explicitly say “agent”; may age into a broad slogan. |
| 9 | **AgentDevWorks** | Suggests an integrated place where agents perform development work. | Longer and slightly less fluid when spoken. |
| 10 | **NextAgentDev** | Signals next-generation agent-based development. | Word order is unusual and could be harder to remember. |
| 11 | **CodeFutureAI** | Directly connects AI with the future of coding. | Sounds more like a media/consulting brand than developer infrastructure. |
| 12 | **AgentDevFlowAI** | Describes an AI-agent development workflow explicitly. | Longest candidate and too descriptive for a strong primary mark. |

## Rejected or downgraded candidates

- **SpecForge** — rejected as the future canonical identity because the
  unscoped npm package belongs to an unrelated hardware-specification product
  and multiple software projects use the phrase.
- **DeliveryLoom** — rejected by the Product Owner; it also had an exact-name
  GitHub repository collision despite apparently open core domains.
- **AgentDevOS** — core domains and package registries appeared open, but the
  exact GitHub account was occupied.
- **AgentShift**, **CodeFleet**, **AgentLane**, **AgentNative** and
  **BuildMesh** — downgraded because core domains, package names or multiple
  GitHub identities were already occupied.
- **AgentWeft**, **BuildLoom**, **AgentMill** and **DevMill** — available in
  some developer namespaces, but their `.com` domain was registered and their
  connection to software development was less immediate.

## Recommendation

Carry three names into direct trademark and registrar review:

1. **CodeAgentOS** — clearest description and best balance of brevity,
   technical meaning and future platform positioning.
2. **AgentBuildOS** — strongest if the product should emphasize the complete
   delivery lifecycle rather than code alone.
3. **AgentCodeKit** — safest expectation-setting if the product remains a lean
   installable toolkit instead of becoming a platform.

Do not announce or rename yet. The owner should directly search exact and
similar marks, check live registrar checkout availability, and claim the chosen
`.com`, `.dev`, GitHub identity and package scope in one short session. Only
then should the canonical-name Bead be closed and implementation begin.
