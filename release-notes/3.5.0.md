# Nogging 3.5.0

Released 2026-10-31. The full list of changes is in the
[changelog](../CHANGELOG.md).

## Session wake

Finished or blocked sessions are now noticed at once, without an agent
sitting awake to watch them. A small script looks at every Lead once a minute,
handles the routine cases itself and wakes the Orchestration Agent only when a
decision is needed.

**It is on by default.** A new install has `session_dispatch.enabled: true`, and a
repository with no such key reads as on. Updating does not change a value you
already set, `false` included. If you want the old behaviour, switch it off in
`.nogging/config.json`:

```json
"session_dispatch": {"enabled": false}
```

What it does:

- It sends fixed nudges to idle Leads, for example one that stopped with uncommitted
  work or without a pull request.
- It tracks CI on open pull requests and tells a Lead which checks are red.
- It holds what needs a decision as one short digest for the orchestrator.
- A Lead ends its work with `nogg session signal done|blocked "<reason>"`, which
  `session watch` and the pass report as a fact.

What it does not do: it runs no model, never merges, never writes a plan, never
answers a question a session is asking, and retires a merged session only if you set
`retire_merged: true`.

**Pause and resume.** `nogg pause --days 3` (or `--until`) holds nudges, digests and
scheduled loops for up to 60 days, and `nogg resume` ends it early. What was held goes
out as one digest when it ends. `--keep-loop <name>` keeps one loop running.
`nogg pause --status` shows what is in force.

**Quiet hours.** `session_dispatch.wake.quiet_hours` (for example `["22:00-07:00"]`)
is a regular window in which the orchestrator is never woken. Nudges and CI tracking
continue.

**What it costs.** The pass itself uses no tokens. Tokens are spent only where a model
turn starts: a nudge costs one turn of that Lead, a digest costs one short orchestrator
turn, a keep-warm costs a cached read of the orchestrator's context, and a cold start
rewrites that context into the cache. Compaction keeps the orchestrator's context
between about 45k and 200k tokens.

Without an orchestrator session or a loops timer nothing fails: the digest waits in the
queue, and `nogg doctor` prints one note for each missing piece. See
[Session wake](../docs/session-wake.md).

## Scheduled loops

`nogg loop add|list|show|log|pause|resume|approve|remove` manage host-approved recurring
work. A `send` loop delivers its prompt to the idle Orchestration Agent. A `launch` loop
starts a fresh, bounded `loop` session with the loop's exact agent, tier and authority,
and stops it when it finishes. `init` and `update` render the
`nogg-loops-<slug>.timer`, and `doctor` reports the timer and any stalled or unapproved
loop. See [Scheduled loops](../docs/scheduled-loops.md).

## Agent routing

An optional `.nogging/agent-routing.json` lists, per role, the agents to try in order.
`session launch` without `--agent` starts the first entry that passes the binary,
authority, backend, model and usage checks, and says why it skipped the others.
`nogg route check` validates the file. With no file nothing changes. See
[Configuration](../docs/configuration.md#agent_routing_file).

## Pi extensions

`.pi/nogging/` is a home for optional Pi extensions that Pi never discovers on its own.
The first one, `glm-usage`, shows your Z.ai coding-plan quota in Pi's footer and feeds
`nogg usage --agent pi`. Enable extensions with the `pi_extensions` config key or with
`nogg pi-ext install`. `init` and `update` copy the home and enable nothing. See
[Pi extensions](../docs/pi-extensions.md).

## Smaller changes

- The Z.ai usage probe accepts `CREDIT_LIMIT` windows.
- `session watch` reads one evidence order for every agent, including herdr's
  `agent_status`.
- A Lead launched for a Bead stays on that Bead until its kickoff.
- The release procedure now checks the documentation site before the tag.
