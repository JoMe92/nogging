# Nogging 3.6.0

Released 2026-11-01. The full list of changes is in the
[changelog](../CHANGELOG.md).

## Test policy and test control

Agents write tests, and left alone they write a lot of them. A week-old repository can
end up with an hour-long suite that every agent runs before every commit, and
development stops while it runs. 3.6.0 gives a repository that uses Nogging a policy
for what to test and a set of commands that keep the cost in sight.

**The policy.** A short, framework-neutral [testing policy](../docs/testing-policy.md)
ships with Nogging, and every agent is pointed at it. In short: always test the
behaviour a change adds or alters; do not test the framework, trivial code or the same
thing twice; pick the cheapest level that proves the change; mock only at real process
boundaries; build expensive setup once per run; never sleep for real; and keep the suite
honest. The code reviewer checks test value, and a task in `tasks.md` carries a `Tests:`
field with a size.

**The stages.** One command per testing moment, each run quietly under a time budget:

```bash
./scripts/nogg test changed    # while working
./scripts/nogg test commit     # before each commit
./scripts/nogg test bead       # once per Bead, before closing it
```

Agents and launch prompts use these instead of running `scripts/test` once per Bead.
With no configuration they run what the repository already has. To use your own runner,
set `testing.stages` in `.nogging/config.json`, and `testing.budgets` for the seconds a
stage may take:

```json
"testing": {
  "stages": {
    "changed": "pytest -q {test_files}",
    "bead": "pytest --testmon --junitxml={junit}"
  },
  "budgets": {"changed": 120, "bead": 600}
}
```

A budget reports and never kills a run. A stage that ran nothing says `skipped` and
never looks green. `bead` and `full` also share two host-wide slots, so several agents
cannot start several heavy suites at once.

**The full suite is deliberate.** Where CI runs your tests, `nogg test full` is locked
and exits 77. To run it anyway, pass `--allow-full "<reason>"`; the reason is recorded.
`--release` is for an operator shell or the Orchestration Agent, and `--nightly` for the
timer. A plan may not demand the full suite either: `nogg validate` and `materialize`
refuse a new task whose `Check:` does.

**Does CI really run tests?** `nogg doctor` asks `gh` and warns when CI is configured but
no test job is found. Where no CI runs tests, `init` and `update` render a nightly
fallback timer, `nogg-nightly-<slug>.timer`. Nothing is enabled for you; `doctor` says
when to enable it. It runs the full suite once per commit at low priority in a separate
worktree, and a failed run is a `doctor` WARN and one digest item.

**Reading the cost.** `nogg test report [--days N] [--json]` shows runs, failures, median
seconds and over-budget runs per stage and day, the week-over-week change, the slowest
tests and the Beads whose tests exceed `task_sizing.bead_test_lines`. `token-usage report
--group-by bead` adds tests added and deleted, skips added and stage seconds per Bead.
`doctor` notes a stage that is getting slower.

**The integrity rule.** Deleting a test, adding a skip or lowering a file's assertion count
is sometimes right, but never silently. `nogg test bead` ends by checking the branch;
such a change needs a `Test-Integrity: <reason>` trailer on a commit and a `discovery`
note on the Bead. `testing.integrity` is `report` by default and `enforce` makes it fail
the stage. Enforcing it in CI as well is an opt-in line in your workflow, in a job that
fetches the full history and the base ref:

```yaml
- run: scripts/check-test-integrity "origin/${GITHUB_BASE_REF}" --enforce
```

**Upgrading.** An existing repository with no `testing` block keeps working. `nogg update`
prints one line saying so, and a malformed value is only a `doctor` WARN. Nothing about
your suite changes until you set `testing`. See [Test control](../docs/test-control.md)
and [Configuration](../docs/configuration.md#testing).

## Statusline preview and removal

`nogg usage install-statusline --dry-run` shows the wrapper, the composed command and a
diff of Claude's `settings.json`, and writes nothing. A real install now backs up
`settings.json` first. `nogg usage uninstall-statusline` restores only the `statusLine`
key and removes the wrapper.

## Session wake fixes

- A Codex session stopped by its usage limit is now reported as `limit`, not `idle`. The
  dispatcher waits for the reset time and resumes it once.
- The Pi lifecycle extension waits longer for each event, so a slow start no longer drops
  a Pi session's first events.
- A pull request's CI is judged by the newest run of each check, so a failure that a later
  re-run superseded no longer keeps the pull request red.
