## Context

See proposal.md for motivation. `scripts/nogg` currently rejects every non-Claude orchestrator; its supervisor, trust check, adoption fallback and resume lookup assume Claude. The canonical lock, unit and tmux singleton already resolve from the main checkout. `stop` disables the service; there is no matching operator-facing `start` command. The current native launch already records exact Claude session IDs; older specification prose about `--continue` must not reintroduce latest-conversation selection.

SPEC-8prb's 2026-10-21 report (draft PR #269, commit `9ea8e91`) establishes that Codex 0.163.0 retained a harmless execpolicy denial under danger-full-access/never, wrapped startup added global scratch-project trust, and an inherited pending-first-input variable seeded parent instructions into a new session. The final configuration hashes were restored and owned probes stopped. Native exact resume and a sanitized Happier round trip were observed; they do not establish unattended trust isolation or exact Happier resume. The report remains unchanged as historical evidence.

The installed Happier CLI exposes `codex`, session status/stop and exact Happier-session resume. Its help is evidence of advertised interfaces, not proof of unattended startup, exact Codex-thread recovery or policy propagation. A regular Happier session created by the operator is independent of the Nogging singleton.

The canonical recovery report has existing unrelated mixed worktrees, a missing recorded worktree and paused rebase journals. They are preserved for their owners; this plan neither repairs nor incorporates their changes. Doctor reported no change ready to archive. Pending discoveries were reviewed; the relevant ones are carried into Decisions 1, 4 and 8. Existing discovery labels remain pending where this plan does not resolve their original tasks.

## Goals / Non-Goals

Goals: one owned orchestrator across both runtimes; durable operator intent; verified conversation identity; remote control that corresponds to the actual managed orchestrator; role-scoped authority; backwards-compatible installation.

Non-goals: simultaneous orchestrators, cross-provider conversation translation, conversion of the standalone Happier operator session, new agent runtimes, herdr orchestration, globally relaxed Codex policies, or implementing the change during planning. Claude through Happier is deferred; Claude retains native Remote Control.

## Decisions

### 1. Retest the revised contract with explicit trust prerequisites

TASK-DRO-001 (`SPEC-8prb`) remains the existing compatibility gate. Preserve the blocked 2026-10-21 report and append a clearly dated revised-contract run or a new dated report; never rewrite its failed findings as passes. Retest native initialization, exact native and Happier conversation resume, inherited-environment isolation, effective model/effort/approval/network and retained execpolicy, attributable remote/native IDs, owned-process liveness and complete stop.

Before live initialization the operator must explicitly prepare and trust the disposable repository and required runtime configuration/hook layers outside the unattended launch. Record that setup as a prerequisite and take immutable configuration/rule baselines afterwards. An approved directory description or trusted ancestor is not evidence of exact runtime trust; invocation-only trust and the hook-trust flag are not established by the earlier run. Do not accept dialogs or let Happier establish the prerequisite implicitly. If it is missing or unobservable, leave the Bead blocked with the exact operator remedy and run no agent.

Run bounded inert probes on a private host-born tmux socket, using only the approved disposable context and existing native authentication without copying credentials. Sanitize the child environment before any first launch. For Codex, a harmless forbidden sentinel must remain denied while an independently allowed benign command succeeds; retained rules are now a required pass. Record actual turn policy and test benign backend network reachability separately from provider API connectivity.

Verify exact native and Happier IDs with attributable receipts and a unique inert marker. Both local process ownership and scoped remote stop evidence are required; a pane exit alone or a stale remote active flag alone proves neither survival nor termination. The CLI wrapper inside owned tmux remains the chosen architecture; no exec-only replacement, rule bypass, masked policy directory or implicit account change is authorized.

Any global trust/configuration mutation after the post-setup baseline is a failure. Stop only the owned runtime, preserve redacted evidence and return the task to blocked. Never restore a whole user file over concurrent changes; operator recovery must distinguish owned changes from unrelated edits. A successful retest, reviewed against this revised contract, is required before closing TASK-DRO-001. Planning changes alone do not unblock it or satisfy missing live evidence.

### 2. Canonical persistent selection and an explicit start command

Add `orchestrator start [--agent claude|codex] [--control native|happier]`. Store desired selection and per-runtime resume checkpoints atomically in versioned canonical `.nogging/state/orchestrator.json`. This is operator state, not a tracked change to `.nogging/config.json`; native default configurations do not acquire a mandatory Happier dependency. Explicit arguments override persisted selection. Without a prior selection, Claude/native is the legacy default; an explicitly selected new Codex runtime defaults to Happier unless `--control native` is supplied. When changing only the agent, resolve that agent's default control rather than inheriting an incompatible old control. Claude/happier and unsupported runtimes fail before mutation.

`start` preflights runtime, authority, selected remote integration, installation and exact repository/configuration-layer trust before changing desired state or launching an agent. Missing or unknown Codex trust is a hard prelaunch refusal with instructions for an explicit operator setup; Happier is never invoked to create trust. Apply the same preflight to run, full restart and cold service recovery. Supervisor-only adoption verifies the existing owner and does not recreate trust. The command installs/re-enables the existing rendered per-repository unit when necessary, reloads user units and starts it. It does not install lingering, log in, accept workspace trust, write user-global settings or launch unobserved fallback processes. Missing prerequisites fail with a concrete operator remedy; optional lingering is reported separately. The unit continues to execute `orchestrator run`, which reads the canonical selection. A manual `run` with no selection state keeps the Claude/native behavior.

Starting the same healthy selection is idempotent. A different selection while the unit, supervisor lock or owned agent is live is refused before changing state. Switching is `stop` -> verify no owned live process/remote session -> `start --agent ...`; no automatic failover on quota or provider failure. A stopped selection and each provider's checkpoint survive `stop` for the next start. Corrupt or unknown-version state is preserved and rejected with recovery guidance, never replaced by a Claude guess. Linked-worktree start/status/stop/restart resolve the main checkout; `run` still refuses from a linked checkout.

### 3. Preserve runtime-specific authority and the Codex floor

Ship `.nogging/launch-profiles/orchestrator.codex.toml` using verified host access (`danger-full-access`, approval `never`, network enabled) while retaining all loaded Codex execpolicy denials. Claude keeps its existing unrestricted orchestrator exception. Do not pass `--ignore-rules`, disable/rename/mask rule directories, change shared/global policy, or turn a forbidden operation into an allowed one through another shell or executable. A floor-denied action is reported to the operator; it is not retried through a workaround.

Only the explicit Codex orchestrator role/profile receives the host policy and exemption from the execution OpenSpec fence. The command floor remains active (`floor_lifted: false`). Status/list/doctor label this `HOST-ACCESS (command floor retained)`, never FULL-ACCESS. Record the effective policy, network setting, loaded-rule status and provenance; unknown evidence cannot be labelled verified. Claude alone retains the existing floor-lifted FULL-ACCESS label. Ordinary lead/planning/specialist roles selecting an orchestrator profile must receive only their normal role authority or refuse before side effects; no ordinary execution role loses its OpenSpec fence.

Both runtime personas remain orchestrate-only by default. The permission to perform one planning/code task still requires explicit takeover, a canonical planning lock for planning and a named claimed Bead for execution. Codex takeovers remain subject to execpolicy. Product Owner sign-off remains human. Supported `scripts/nogg` lifecycle APIs remain the intended operational interface; they are not a general-purpose bypass for a denied arbitrary command.

Reuse the native exact-thread receipt/resume machinery and shared persona. Forward verified model/effort through the installed wrapper contract: Codex defaults to the Product Owner's Luna policy (`gpt-6-luna`, medium), with explicit supported overrides recorded. Claude model behavior, ordinary-role floors and the manual Claude permission template remain unchanged. The runtime-neutral persona includes Codex's local workflow entry points without relying on Claude slash-command dispatch.

### 4. One tmux-owned supervisor and provider-specific exact recovery

Keep the existing canonical systemd unit, orchestrator lock and fixed tmux session name. Happier is a remote-control adapter around Codex inside that owned session, not a replacement session backend. No new herdr path is introduced; the existing session-backends specification remains valid.

Persist requested agent/control separately from observed identity, including managed session name, runtime conversation ID, Happier session ID when applicable, working directory, role, timestamps, effective authority, readiness and exit reason. Checkpoint each `(agent, control)` independently so stop/switch/switch-back can resume its previous exact conversation without overwriting the other provider's checkpoint. Keep remote IDs distinct from Codex thread IDs. Native/Happier changes do not transfer a thread implicitly.

A live session is adopted only when its durable ownership, main checkout, role, runtime/control and process/remote identities match. A recordless or ambiguous tmux singleton is reported as unknown and refused, never synthesized as Claude or killed as foreign. Legacy records without agent mean Claude only when existing Claude ownership/ID evidence verifies that interpretation. Preserve unrelated transcripts and regular Happier sessions.

Restart and service recovery use the matching checkpoint. First use cold-starts with the current persona. A recorded ID whose conversation is missing, corrupt, owned by another context or incompatible fails with a remedy; do not silently resume the cwd's newest conversation or cold-start after losing known state. A verified prior launch that never established a conversation can retry its initial cold start. Supervisor-only restart adopts the same owned live session and starts no second agent. A full restart refreshes runtime configuration and preserves its exact conversation. Keep the current guard against terminating one's own control session mid-restart.

Discovery context: SPEC-3nwm documented Claude trust/disclaimer hazards and latest-cwd resume ambiguity. SPEC-22a8 and SPEC-t374 document incomplete Codex lifecycle acceptance, null process ownership and unverified message delivery. Do not treat those older reports as acceptance of this design. Launch must establish the host-owned process and exact runtime receipt; user messages need actual receipt evidence, and unverified delivery is not automatically resent.

### 5. Happier access belongs to the managed Codex session

Before starting Codex/happier, construct its environment from an explicit allowlist of required existing account/home/server/runtime locators. Remove inherited parent session/thread identifiers, pending first input (including `HAPPIER_DAEMON_PENDING_FIRST_INPUT`), lifecycle/service-spawn context and unrecognized Happier session-control variables. Only this launch's validated persona and operator message may seed its input. Preserve the selected account/server intentionally, never copy secrets or silently replace provider authentication. Test startup from a deliberately contaminated parent environment.

For Codex/happier, the wrapper supplies the validated authority, model, effort, cwd and persona, captures its own remote session ID and exact Codex thread, and reports readiness only after backend initialization and remote registration. Use only documented supported interfaces verified in Decision 1. `status` displays the actual Happier session ID and a link only when the integration supplies one; operator instructions tell the user to open that exact session in Happier. Never infer an ID by selecting the newest remote session for the path.

Remote readiness and agent liveness are separate. An API timeout produces unknown/degraded remote state and bounded retry/backoff, not a second agent. Authentication failure or unsupported integration fails explicitly without auto-login, account switch, provider switch or native fallback. A live Codex process does not imply Happier is reachable. Native Codex is available only through explicit native selection and reports that mobile access is not configured.

`stop` disables future automatic service restart, explicitly stops the verified owned remote session through the supported integration, terminates/reconciles its owned runtime/adapter with the existing graceful timeout, and confirms remote inactivity together with absence of the captured PID/start-time process identities. Preserve an unknown state when evidence disagrees. Never infer a surviving agent solely from a stale active flag or successful stop solely from a closed pane. Never archive/delete conversations merely to stop execution. If termination or remote verification is uncertain, report partial/unknown stop, retain ownership/checkpoint evidence and refuse a new start until reconciled. A transient remote outage must not discard the singleton or launch a replacement. Foreign Happier sessions and unrelated tmux panes are never touched.

### 6. Diagnostics, payload and migration are part of the feature

Expose desired agent/control and observed runtime/conversation/remote IDs, readiness, exact-trust preflight result, runtime-specific authority, retained-floor status and exit reason in `orchestrator status` (including versioned JSON), `session list`, `doctor` and recovery evidence. Keep existing native log/attach/send operations useful for both runtimes; route transport-specific inspection/delivery through the adapter when a wrapped Codex TUI is unavailable. A normal Happier session remains a normal session and cannot acquire the orchestrator role from its title/tag. Use the existing source-attributed token collection; unknown wrapped runtime usage remains unknown, never borrowed from another Codex session or reported as zero.

Update package manifests/helper contracts, rendered-unit handling, init/update/remove and installation/security/operating/architecture/recovery/Codex guides, canonical AGENTS.md and installed instruction copies, plus `.codex/prompts/orchestrate.md` with matching Claude entry-point guidance. Update preserves operator selection, checkpoints, unrelated settings and locally modified managed files using the existing pending-update mechanism. Init without systemd remains inert; native Claude works with no Happier installed. Removal follows explicit existing removal semantics and never deletes provider transcripts.

Migration reads a legacy verified Claude record as Claude/native, preserving its exact ID. Do not start a service during package update. Rollback is explicit stop, verify termination, then select Claude/native using the installed version's supported state format; preserve a backup of new state before a downgrade. Do not edit state while an old supervisor is live.

### 8. Meaningful isolated validation and unsigned live acceptance

Focused suites use fake runtime/Happier/systemctl responses, temporary HOME/state/config, scratch Git repositories, bounded timeouts and short private socket paths. They must not connect to real Dolt/Beads, alter user settings, rely on PID ranges, require real namespaces, signal the fleet, run a background production service or recursively run the full suite. Include missing exact trust and configuration-layer trust (refusal before any runtime spawn), missing auth/profile/CLI, unsupported flags, global-config mutation detection, contaminated inherited initial input, retained Codex sentinel denial plus an allowed command, honest authority labels, corrupt state, exact ID mismatch, cross-runtime adoption, concurrent starts, graceful-stop timeout, a detached surviving remote process, stale remote activity, API outage and ordinary-role authority isolation. Verify native Claude still works without Happier and herdr defaults cannot move the orchestrator off tmux.

TASK-DRO-007 runs the relevant existing suites and one full `scripts/test` after integration. After explicit operator preparation of trusted scratch roots and post-setup policy baselines, TASK-DRO-008 performs actual scratch-host acceptance for Claude/native, Codex/native and Codex/happier: cold start/persona, benign remote request and verified reply, own exact resume after process loss and service restart, reboot-equivalent recovery, supervisor-only adoption, stop from a linked checkout, repeat stop, stop/switch/switch-back, second-start refusal and survival of unrelated sessions. Verify at most one agent at every stage and that stop leaves no remotely operable owned process. Systemd reboot-equivalent tests alone do not prove an actual host reboot; report the distinction.

The real tmux birth must occur in the host namespace; SPEC-iohv shows that current namespace warnings can be wrong (SO_PEERCRED field order), so do not use that warning as proof. Its nudge timing discovery also means an exit-zero/queue acceptance alone is insufficient proof of a delivered mobile instruction. These findings stay with their original Beads; acceptance can record a blocking discovery if they prevent the scoped checks, never fix them ad hoc here. The packed orchestrator fixture issue from SPEC-t374 is relevant regression coverage: only execution roles should be asserted fenced; TASK-DRO-007 reconciles fixtures with the actual role contract.

Write versioned, redacted, dated evidence in `docs/acceptance/<date>-dual-runtime-orchestrator.md`, leave `Signed-off-by:` empty, and distinguish pass/fail/skipped/unknown. Quota, missing authorization or unverified mobile behavior means acceptance remains incomplete. No unrelated Bead is closed or claimed to make the report appear complete.

## Risks / Trade-offs

- Happier's wrapper may detach or expose insufficient identity/resume controls -> compatibility gate blocks dependent work rather than shipping an unowned agent.
- Codex floor can deny an operation requested during orchestration/takeover -> report it for operator action; keep the denial and avoid automatic bypass.
- Wrapped startup can mutate global trust -> refuse unprepared or unknown roots before spawn; verify post-setup baselines and block on any runtime mutation.
- A parent can seed unintended startup input -> allowlist child environment and prove the expected first input in live evidence.
- Provider or remote outage resembles process death -> reconcile process and remote identities separately, retain unknown ownership and bound retries.
- Host access and an auto-resumed persona remain a standing injection target -> preserve explicit opt-in, runtime-specific authority labels, retained Codex rules, takeover discipline, canonical singleton and human sign-off.
- Existing live acceptance gaps are not proof of runtime failure or success -> use new scratch evidence, retain unsigned reports and block acceptance honestly.
